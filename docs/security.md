# Security / 安全说明

## Comment Markdown and Math / 评论 Markdown 与公式

- Comment content is stored as user-submitted plain Markdown text.
  评论内容以用户提交的原始 Markdown 文本存储。
- Markdown rendering happens only in the frontend.
  Markdown 仅在前端渲染。
- Raw user HTML is escaped before Markdown parsing and is not supported as active HTML.
  用户提交的原始 HTML 会在 Markdown 解析前转义，不会作为可执行 HTML 使用。
- Rendered Markdown HTML is sanitized with DOMPurify before insertion into the page.
  Markdown 渲染结果插入页面前会使用 DOMPurify 清理。
- The Admin dashboard uses the same sanitized Markdown and KaTeX rendering for previews.
  后台预览使用相同的安全 Markdown 和 KaTeX 渲染流程。
- Comment links are restricted to safe protocols and receive `target="_blank"` and `rel="nofollow noopener noreferrer"`.
  评论链接仅允许安全协议，并添加 `target="_blank"` 与 `rel="nofollow noopener noreferrer"`。
- KaTeX uses `throwOnError: false`; code blocks and inline code are ignored by the math renderer.
  KaTeX 使用 `throwOnError: false`，公式渲染器会忽略代码块和行内代码。

## Comment Source Bans / 评论来源封禁

- IP bans use the SHA-256 `ip_hash` generated by the Worker. Raw IP addresses are not used as the primary ban value.
  IP 封禁使用 Worker 生成的 SHA-256 `ip_hash`，不会将明文 IP 作为主要封禁值。
- Device bans use a lightweight SHA-256 fingerprint generated in the browser. Only the hash is sent to the Worker.
  设备封禁使用浏览器生成的轻量 SHA-256 指纹，只会向 Worker 发送 hash。
- Raw browser and screen properties used to create the device fingerprint are not sent to the backend.
  用于生成设备指纹的原始浏览器和屏幕信息不会发送到后端。
- Device fingerprints are moderation aids, not strong identities. Clients can omit or spoof them, and browser or device changes can produce a different fingerprint.
  设备指纹只是审核辅助信号，不是强身份标识。客户端可以省略或伪造该值，浏览器或设备变化也可能产生不同指纹。
- IP bans may affect multiple users sharing the same public network.
  IP 封禁可能影响共享同一公网网络的多个用户。
- Unsalted SHA-256 hashes of IPv4 addresses should not be treated as anonymous data because the address space can be searched.
  不应将未加盐的 IPv4 SHA-256 hash 视为匿名数据，因为其地址空间可被遍历。
- The existing `comments.ip` field remains for backward compatibility. Spam & Ban uses `ip_hash`, and the Admin UI emphasizes shortened hashes.
  现有 `comments.ip` 字段为兼容性保留。Spam & Ban 使用 `ip_hash`，后台界面主要展示缩短后的 hash。
- Ban records and source hashes are available only through Admin Token-protected endpoints and the Admin dashboard.
  封禁记录和来源 hash 仅能通过受 Admin Token 保护的接口与后台访问。
- Expired bans remain visible in the Admin Bans view but no longer block new comments.
  已过期封禁仍会显示在后台 Bans 视图中，但不会继续阻止新评论。

## Secrets and Deployment / 密钥与部署

- Do not commit a real `worker/wrangler.toml` or `secrets.production.json`.
  不要提交真实的 `worker/wrangler.toml` 或 `secrets.production.json`。
- Store `ADMIN_TOKEN` only as a Worker secret and in trusted administrator browsers. It grants access to moderation data and unban actions.
  `ADMIN_TOKEN` 只能作为 Worker secret 保存，并仅在可信管理员浏览器中使用。它可以访问审核数据并执行解除封禁操作。
- Store `TURNSTILE_SECRET_KEY` only as a Worker secret.
  `TURNSTILE_SECRET_KEY` 只能作为 Worker secret 保存。
- `PUBLIC_TURNSTILE_SITE_KEY` is public and can be included in frontend assets.
  `PUBLIC_TURNSTILE_SITE_KEY` 是公开 key，可以包含在前端资源中。
- `CLOUDFLARE_API_TOKEN` is for deployment only and must not be committed.
  `CLOUDFLARE_API_TOKEN` 仅用于部署，不能提交到 Git。
- `dist/frontend/yuucomments.config.js` may contain only the public Worker API URL and Turnstile site key.
  `dist/frontend/yuucomments.config.js` 只能包含公开的 Worker API 地址和 Turnstile site key。
- Before production deployment, confirm the allowed origins in `worker/src/utils/cors.ts` match the real site domains.
  正式部署前，请确认 `worker/src/utils/cors.ts` 中允许的来源与真实站点域名一致。

## Anonymous Likes / 匿名点赞

- Anonymous likes use `visitor_hash` to limit duplicate likes without requiring login.
  匿名点赞使用 `visitor_hash` 限制重复点赞，无需登录。
- `visitor_hash` is derived from request IP and User-Agent; raw values are not stored in `comment_likes`.
  `visitor_hash` 根据请求 IP 和 User-Agent 生成，`comment_likes` 不保存这些原始值。
- This is not a strong identity system. Device, browser, or network changes may be treated as a different visitor.
  这不是强身份系统。更换设备、浏览器或网络后，可能会被识别为不同访客。
