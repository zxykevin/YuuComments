# Security

## Comment Markdown and math

- Comment content is still stored as user-submitted plain Markdown text.
- Markdown rendering happens only in the frontend.
- Raw user HTML is escaped before Markdown parsing, so it is not supported as active HTML.
- Markdown HTML is sanitized with DOMPurify before it is inserted into the comment list.
- The admin dashboard uses the same sanitized Markdown and KaTeX rendering for comment previews.
- Comment links are restricted to safe protocols and receive `target="_blank"` and `rel="nofollow noopener noreferrer"`.
- LaTeX formulas are rendered with KaTeX using `throwOnError: false`, and code blocks / inline code are ignored by the math renderer.

## Comment source bans

- IP bans use the SHA-256 `ip_hash` value generated by the Worker. Raw IP addresses are not used as the primary ban value.
- Device bans use a lightweight SHA-256 fingerprint generated in the browser. Only the hash is sent to the Worker; the raw browser and screen properties are not sent.
- Device fingerprints are a moderation aid, not a strong or permanent identity system. Clients can omit or spoof the value, and browser changes, privacy tools, or device changes can produce a different fingerprint.
- IP bans may affect multiple users sharing the same public network.
- An unsalted SHA-256 hash of an IPv4 address should not be treated as anonymous data because the possible address space can be searched.
- The existing `comments.ip` field remains available for backward compatibility. Spam & Ban uses `ip_hash` as the ban value, and the Admin UI emphasizes shortened hashes instead of raw IP addresses.
- Ban records and shortened source hashes are visible only through Admin Token-protected endpoints and the Admin dashboard.
- `ADMIN_TOKEN` grants access to moderation data and unban actions. Store it only as a Worker secret and in trusted administrator browsers.
- Expired bans remain visible in the Admin Bans view but do not block new comments.

- 不要提交真实的 `worker/wrangler.toml`
- 不要提交 `secrets.production.json`
- `ADMIN_TOKEN` 只应保存在本地安全位置或 Worker secret 中
- `TURNSTILE_SECRET_KEY` 是私密 key，只能作为 Worker secret 保存
- `PUBLIC_TURNSTILE_SITE_KEY` 是公开 key，可以放前端
- `CLOUDFLARE_API_TOKEN` 只用于部署，不能提交到 GitHub
- `dist/frontend/yuucomments.config.js` 只能写入公开的 Worker API 地址和 Turnstile Site Key
- 上线前请确认 `worker/src/utils/cors.ts` 中的白名单域名已经替换为真实站点域名
- v0.1.3 的点赞功能使用匿名 `visitor_hash` 限制重复点赞，不需要登录
- `visitor_hash` 由请求 IP 和 User-Agent 计算得到，`comment_likes` 表不保存原始 IP 或原始 User-Agent
- 点赞不是强身份系统，换设备、换浏览器或换网络可能被视为不同访问者
